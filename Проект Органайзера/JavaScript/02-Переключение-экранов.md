## 1. Задача и границы урока

В первом уроке мы научились находить HTML-элементы и менять их текст. Теперь применим тот же способ для навигации по Organizer: пользователь нажимает кнопку «Проекты», браузер скрывает раздел «Задачи» и показывает раздел «Проекты» **без перезагрузки страницы**. Кнопка «Календарь» аналогично открывает календарь.

На этом шаге подключаем **только основные экраны внутри элемента `#appMain`**. Экраны входа и регистрации (`loginScreen`, `registerScreen`) находятся вне `#appMain` и будут обрабатываться позднее, на этапе авторизации. Мы не открываем диалоговые окна, не назначаем активный пункт бокового меню и не создаём историю переходов браузера: это отдельные шаги.

## 2. Что уже подготовлено в HTML

В разметке есть кнопки, например:

```html
<button type="button" data-screen-target="projectsScreen">Проекты</button>
<button type="button" data-screen-target="calendarScreen">Календарь</button>
```

Есть и соответствующие экраны, расположенные в `<main id="appMain">`:

```html
<section class="screen" id="tasksScreen">...</section>
<section class="screen" id="projectsScreen" hidden>...</section>
<section class="screen" id="calendarScreen" hidden>...</section>
```

Идентификаторы в `data-screen-target` совпадают с `id` экранов. В начале отображается экран задач; остальные экраны содержат атрибут `hidden`, поэтому скрыты.

В `style.css` уже действует правило:

```css
[hidden] { display: none !important; }
```

Мы используем существующие атрибуты, ничего не переделывая в HTML и CSS.

## 3. Как работает переход

Код выполняет последовательность действий:

1. Находит кнопки с атрибутом `data-screen-target`.
2. Находит основную область `#appMain` и размещённые в ней элементы `section.screen`.
3. Подписывается на нажатие каждой кнопки.
4. При нажатии читает имя целевого экрана из `data-screen-target`.
5. Проверяет, что такой экран существует и находится внутри основной области приложения.
6. Скрывает все остальные основные экраны и показывает только выбранный.

Например: пользователь нажал «Проекты» → получено имя `projectsScreen` → скрывается `tasksScreen` → показывается `projectsScreen`.

## 4. Новые конструкции JavaScript

### 4.1. Событие `click` и метод `addEventListener()`

**Событие** — сигнал о том, что произошло действие или изменение, например нажатие кнопки. `click` — название события активации кнопки мышью, клавиатурой или другим предусмотренным браузером способом.

Метод `addEventListener()` сообщает браузеру: когда у этого элемента произойдёт названное событие, выполни переданную функцию.

```javascript
button.addEventListener("click", () => {
  showScreen(button.dataset.screenTarget);
});
```

Функция `() => { ... }` — **стрелочная функция**. Мы не вызываем её немедленно: передаём браузеру для выполнения при будущем нажатии. Функция `showScreen()` вызывается уже внутри обработчика.

### 4.2. `dataset` и атрибуты `data-*`

HTML позволяет задавать собственные атрибуты с префиксом `data-`, предназначенные для хранения сведений об элементе. Например, `data-screen-target="projectsScreen"` обозначает экран, который должна открыть кнопка.

JavaScript читает такие атрибуты через свойство `dataset`:

```javascript
button.dataset.screenTarget
```

В имени свойства дефисы после `data-` преобразуются в запись с заглавной буквой: `screen-target` → `screenTarget`. Для кнопки «Проекты» результат — строка `"projectsScreen"`.

Благодаря этому **один обработчик подходит для разных кнопок**. Нам не требуется писать отдельную функцию на каждый раздел.

### 4.3. `hidden` и его изменение

`hidden` — логическое свойство HTML-элемента. Присваивание `true` скрывает его, `false` — показывает:

```javascript
screen.hidden = true;  // Скрыть экран.
screen.hidden = false; // Показать экран.
```

Для всех основных экранов мы используем одну строку:

```javascript
screen.hidden = screen !== targetScreen;
```

Выражение `screen !== targetScreen` возвращает `true`, если текущий экран не совпадает с выбранным. Он будет скрыт. Для выбранного экрана результат `false` — экран станет видимым. **В итоге отображается ровно один основной экран.**

### 4.4. `forEach()` — повторить действие для каждого элемента

`querySelectorAll()` возвращает коллекцию `NodeList`. Метод `forEach()` выполняет переданную функцию для каждого элемента этой коллекции.

Мы применяем его дважды: сначала для показа и скрытия экранов, затем для назначения обработчиков кнопкам.

### 4.5. `getElementById()`, `contains()` и `classList.contains()`

`document.getElementById(screenId)` находит элемент по точному значению его `id`. Здесь, в отличие от CSS-селектора `querySelector()`, символ `#` не требуется.

Проверка `mainArea.contains(targetScreen)` убеждается, что найденный элемент лежит внутри основной области. `targetScreen.classList.contains("screen")` убеждается, что у него есть CSS-класс `screen`.

Все проверки нужны, чтобы ошибка в атрибуте кнопки не заставила программу скрыть рабочий экран или показать посторонний элемент. Если цель неверна, `console.warn()` выводит предупреждение в консоли, а `return` прекращает выполнение функции, ничего не меняя.

### 4.6. Именованная функция `showScreen()`

```javascript
function showScreen(screenId) {
  const targetScreen = document.getElementById(screenId);

  if (mainArea === null || targetScreen === null ||
      !mainArea.contains(targetScreen) || !targetScreen.classList.contains("screen")) {
    console.warn("Неизвестный экран:", screenId);
    return;
  }

  screens.forEach((screen) => {
    screen.hidden = screen !== targetScreen;
  });
}
```

`function` создаёт обычную именованную функцию. `screenId` — **параметр**, то есть значение, которое получает функция при вызове. В разных случаях это будут `"tasksScreen"`, `"projectsScreen"` и другие имена экранов. Функция отделяет действие «показать нужный экран» от обработки нажатия конкретной кнопки.

## 5. Добавленный код урока 2

В конец существующего `script.js` после кода первого урока добавлен следующий фрагмент:

```javascript
// Урок 2. Переключение основных экранов без перезагрузки страницы.
const mainArea = document.querySelector("#appMain");
const screens = document.querySelectorAll("#appMain .screen");

function showScreen(screenId) {
  const targetScreen = document.getElementById(screenId);

  if (mainArea === null || targetScreen === null ||
      !mainArea.contains(targetScreen) || !targetScreen.classList.contains("screen")) {
    console.warn("Неизвестный экран:", screenId);
    return;
  }

  screens.forEach((screen) => {
    screen.hidden = screen !== targetScreen;
  });
}

navigationButtons.forEach((button) => {
  button.addEventListener("click", () => {
    showScreen(button.dataset.screenTarget);
  });
});
```

**Почему не используется Model?** На этом шаге мы пока не читаем и не изменяем данные задач или проектов. Представление (View) отвечает за видимость разделов, а обработчики кнопок играют роль контроллера (Controller). Это простейшее функциональное разделение ответственности; отдельные файлы MVC появятся позже, когда объём кода оправдает их введение.

## 6. Что изменилось в репозитории

Изменён только корневой файл `script.js`: сохранён код первого урока и добавлены функция `showScreen()` и обработчики событий. `index.html` и `style.css` не изменяются. Этот файл Markdown создаётся отдельно от исполняемого кода, поэтому подробные объяснения не перегружают скрипт.

## 7. Как проверить

1. Откройте страницу Organizer в браузере с обновлённым `script.js`.
2. В боковом меню нажмите **«Проекты»** — должен открыться список проектов, а «Мои задачи» исчезнут.
3. Нажмите **«Календарь»**, затем **«Команда»** и **«Задачи»** — каждый раз в основной области должен оставаться только один раздел.
4. В разделе «Проекты» нажмите **«Открыть проект»** — откроется экран подробностей. Нажмите **«Ко всем проектам»**, чтобы вернуться.
5. В разделе «Команда» откройте профиль участника и вернитесь кнопкой **«К команде»**.
6. Верхние кнопки **«Уведомления»** и **«Мой профиль»** также должны открывать соответствующие разделы.
7. В консоли браузера не должно быть ошибок от корректных переходов.

Для дополнительной проверки в консоли можно вызвать `showScreen("несуществующийЭкран")`. Функция должна вывести предупреждение и оставить текущий экран видимым. После обновления страницы снова показывается исходный экран «Мои задачи»: хранение состояния и история переходов ещё не реализованы.

В рамках этого урока кнопки открытия диалогов, сохранение форм, поиск и фильтрация задач остаются неработающими — их очередь придёт позднее.
