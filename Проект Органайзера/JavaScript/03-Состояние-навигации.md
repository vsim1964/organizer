## 1. Что мы делаем и зачем

В уроке 2 кнопки уже переключали основные экраны Organizer. Но после перехода не было видно, какой раздел выбран в боковом меню. Кроме того, внутри раздела «Проекты» есть экран отдельного проекта, а внутри раздела «Команда» — профиль участника. В обоих случаях пользователь должен сохранять ориентир: к какому разделу относится открытый экран.

На третьем шаге добавлены три правила:

1. Боковое меню выделяет текущий раздел.
2. При открытии вложенного экрана выделение остаётся у его родительского раздела. Существующие кнопки возвращают к списку.
3. Переход с неизвестным или неподходящим идентификатором не меняет видимость экранов и выделение меню.

Это дополнение к функции `showScreen()`, а не переписывание приложения. Код первых двух уроков сохранён.

## 2. Что такое состояние навигации

**Состояние** — сведения о текущем положении приложения. В данном случае это открытый экран и соответствующий пункт бокового меню. Например:

- открыт `tasksScreen` — активны «Задачи»;
- открыт `projectsScreen` — активны «Проекты»;
- открыт `projectDetailsScreen` — всё ещё активны «Проекты»;
- открыт `memberScreen` — активна «Команда».

Отдельный глобальный объект состояния здесь пока не нужен: текущий экран можно определить по свойству `hidden`, а активный пункт меню — по атрибуту `aria-current`. В дальнейшем, когда появится больше взаимосвязанных данных, состояние приложения будем организовывать отдельно.

## 3. Как выделяется активный раздел

В HTML боковое меню уже содержит кнопки с `data-screen-target`. Например:

```html
<button class="sidebar__link" type="button" data-screen-target="projectsScreen">Проекты</button>
```

В файле `style.css` уже предусмотрено правило:

```css
.sidebar__link[aria-current="page"] {
  color: var(--color-accent);
  background: var(--color-accent-soft);
  border-color: #b9d9d7;
}
```

Атрибут **`aria-current="page"`** обозначает элемент навигации, представляющий текущую страницу. Он также понятен программам экранного чтения. В нашем одностраничном приложении каждый раздел ведёт себя как отдельная страница.

Находим кнопки именно бокового меню:

```javascript
const sidebarButtons = document.querySelectorAll(".sidebar__nav [data-screen-target]");
```

Точка перед `sidebar__nav` означает поиск по CSS-классу. Пробел означает, что ищем элементы внутри найденного контейнера. Благодаря этому кнопки верхней панели не получают оформление бокового меню.

После выбора экрана обновляем атрибуты всех кнопок:

```javascript
sidebarButtons.forEach((button) => {
  if (button.dataset.screenTarget === activeSection) {
    button.setAttribute("aria-current", "page");
  } else {
    button.removeAttribute("aria-current");
  }
});
```

**`setAttribute()`** добавляет HTML-атрибут или меняет его значение. **`removeAttribute()`** удаляет атрибут. У текущего пункта появляется `aria-current="page"`, у остальных он удаляется. Поэтому одновременно выделен максимум один пункт.

## 4. Как обрабатываем вложенные экраны

Мы уже подготовили в HTML отдельные экраны карточки проекта и профиля участника. Они не имеют собственных пунктов в боковом меню. Вместо этого задаём небольшую таблицу соответствий:

```javascript
const parentScreens = {
  projectDetailsScreen: "projectsScreen",
  memberScreen: "teamScreen"
};
```

Это обычный **объект JavaScript**. Слева записаны имена его свойств, справа — значения. Когда открыт `projectDetailsScreen`, родительский раздел — `projectsScreen`.

Следующая строка определяет, какая кнопка должна быть активна:

```javascript
const activeSection = parentScreens[screenId] ?? screenId;
```

Запись **`parentScreens[screenId]`** обращается к свойству объекта по имени, которое хранится в переменной `screenId`. Оператор **`??`** выбирает правое значение только тогда, когда левое равно `null` или `undefined` (значение отсутствует).

Для вложенного экрана берём имя родителя. Для обычного экрана свойства в таблице нет, поэтому берём исходное имя.

**Возврат уже предусмотрен в HTML.** Например, на карточке проекта есть кнопка:

```html
<button type="button" data-screen-target="projectsScreen">Ко всем проектам</button>
```

Она использует тот же обработчик `click`, что и другие кнопки. Отдельную функцию возврата писать не нужно. На экране участника аналогично работает кнопка «К команде».

Сейчас это возврат к заранее указанному родительскому экрану, а не история произвольных переходов и не кнопка браузера «Назад». Историю браузера пока не изменяем.

## 5. Защита от неверного идентификатора

В начале `showScreen()` остаётся проверка из урока 2:

```javascript
const targetScreen = document.getElementById(screenId);

if (mainArea === null || targetScreen === null ||
    !mainArea.contains(targetScreen) || !targetScreen.classList.contains("screen")) {
  console.warn("Неизвестный экран:", screenId);
  return;
}
```

Проверяем, существует ли основная область; найден ли экран; принадлежит ли он `#appMain`; имеет ли класс `screen`. Оператор `||` означает логическое «или», `!` — отрицание.

Если проверка не пройдена, `console.warn()` пишет предупреждение в консоль, а `return` прерывает работу функции **до изменения любых экранов и кнопок**. Видимый экран и выделение меню остаются прежними.

Кнопки регистрации и входа находятся вне основной области и пока не управляются этим механизмом. Авторизация появится на отдельном этапе.

## 6. Управление фокусом

После успешного перехода вызывается:

```javascript
if (moveFocus) {
  mainArea.focus();
}
```

**Фокус** — элемент, на который сейчас направлен ввод с клавиатуры. В HTML область `#appMain` уже имеет `tabindex="-1"`: она может получить фокус программно, но не включается в обычную последовательность переходов клавишей Tab. Передача фокуса основной области помогает пользователям клавиатуры и вспомогательных технологий перейти от меню к открывшемуся содержимому.

Параметр `moveFocus = true` задаёт значение по умолчанию. При обычных переходах фокус переносится. При первом запуске вызываем:

```javascript
showScreen("tasksScreen", false);
```

Здесь `false` означает: показать начальный экран и выделить «Задачи», но не переводить туда фокус автоматически.

## 7. Что изменилось в коде

Изменён только корневой `script.js`. В нём остались краткие комментарии, а новые конструкции описаны в этом документе. HTML и CSS не менялись: нужные идентификаторы, кнопки возврата и стиль `aria-current` уже существовали.

Основная часть новой логики:

```javascript
const sidebarButtons = document.querySelectorAll(".sidebar__nav [data-screen-target]");

const parentScreens = {
  projectDetailsScreen: "projectsScreen",
  memberScreen: "teamScreen"
};

function showScreen(screenId, moveFocus = true) {
  const targetScreen = document.getElementById(screenId);

  if (mainArea === null || targetScreen === null ||
      !mainArea.contains(targetScreen) || !targetScreen.classList.contains("screen")) {
    console.warn("Неизвестный экран:", screenId);
    return;
  }

  screens.forEach((screen) => {
    screen.hidden = screen !== targetScreen;
  });

  const activeSection = parentScreens[screenId] ?? screenId;

  sidebarButtons.forEach((button) => {
    if (button.dataset.screenTarget === activeSection) {
      button.setAttribute("aria-current", "page");
    } else {
      button.removeAttribute("aria-current");
    }
  });

  if (moveFocus) {
    mainArea.focus();
  }
}
```

Существующие подписки на `click` не меняются. После их установки вызываем `showScreen("tasksScreen", false)`, чтобы задать начальное состояние.

## 8. Проверка результата

1. Откройте Organizer. Изначально должны быть видны «Мои задачи», а в боковом меню выделены «Задачи».
2. Нажмите «Проекты». Отображается список проектов, выделен пункт «Проекты».
3. Нажмите «Открыть проект». Отображаются подробности проекта, но выделенным остаётся «Проекты».
4. Нажмите «Ко всем проектам». Возвращается список, выделение сохраняется.
5. Перейдите в «Команда», откройте профиль участника: выделена «Команда». Кнопка «К команде» возвращает к списку.
6. Переключитесь между «Календарь», «Настройки», «Задачи» и верхними кнопками «Уведомления», «Мой профиль». На основных экранах одновременно виден только один раздел. У верхних разделов без собственного пункта бокового меню ни один пункт бокового меню не выделен; это ожидаемо.
7. В консоли разработчика (`F12` → Console) введите `showScreen("неизвестныйЭкран")`. Должно появиться предупреждение, но открытая страница и выделение не изменятся.
8. Для проверки клавиатуры активируйте кнопку меню клавишей Enter или Space. После успешного перехода фокус переместится в основную область.

## 9. Чего пока не делаем

Не добавляем универсальный стек истории посещений, `history.pushState()`, управление URL, сохранение текущего экрана после перезагрузки, авторизацию, диалоговые окна и операции с данными. Это отдельные задачи следующих этапов. На четвёртом шаге планируется открытие и закрытие диалоговых окон.
