## 1. Что мы реализуем

На предыдущих занятиях научились находить HTML-элементы, переключать основные экраны и выделять активный раздел. Теперь подключаем уже существующие диалоговые окна — небольшие формы, которые открываются поверх текущего экрана.

В `index.html` заранее созданы три окна:

| Идентификатор | Где открывается | Назначение |
| --- | --- | --- |
| `taskDialog` | «Добавить задачу», «Редактировать» на карточке | Форма задачи |
| `projectDialog` | «Создать проект» | Форма проекта |
| `inviteDialog` | «Пригласить участника» | Форма приглашения |

В пределах этого урока реализуем только **открытие и закрытие**. Данные из форм не сохраняются; карточки задач и проектов не меняются, приглашения не отправляются. Кнопка «Редактировать» пока лишь открывает существующую форму задачи, **не заполняя её данными конкретной карточки**. Это будет сделано на уроках о модели задач и редактировании.

## 2. Что такое `dialog`

**`<dialog>`** — стандартный HTML-элемент для диалогового окна. В нашем HTML уже есть пример:

```html
<button type="button" data-dialog-target="projectDialog">Создать проект</button>

<dialog class="dialog-panel" id="projectDialog" aria-labelledby="projectDialogTitle">
  <h2 id="projectDialogTitle">Новый проект</h2>
  <form id="projectForm">
    <!-- Поля формы и кнопки -->
    <button type="submit">Сохранить проект</button>
    <button type="button" data-close-dialog>Отмена</button>
  </form>
</dialog>
```

В отличие от основного экрана, окно `dialog` изначально закрыто и не участвует в навигации между разделами.

Для его открытия используются методы браузера:

- **`dialog.showModal()`** открывает окно в модальном режиме: фон затемняется, взаимодействие с остальной страницей ограничивается до закрытия окна, фокус попадает внутрь.
- **`dialog.close()`** закрывает окно. Браузер снимает модальный режим.
- **`dialog.open`** — логическое свойство: `true`, если окно открыто, и `false`, если закрыто.

В модальном режиме браузер обычно позволяет закрыть окно клавишей **Escape**, без дополнительного обработчика JavaScript. Это встроенное поведение HTML-элемента `dialog`.

Тёмный фон уже описан в `style.css` правилом `.dialog-panel::backdrop`. В этом уроке CSS менять не требуется.

## 3. Как находим кнопки и окна

В HTML существуют два договорённых атрибута:

- `data-dialog-target="taskDialog"` у кнопки означает: при нажатии открой `<dialog id="taskDialog">`.
- `data-close-dialog` у кнопки внутри формы означает: закрой ближайшее диалоговое окно.

Находим эти кнопки и формы:

```javascript
const dialogButtons = document.querySelectorAll("[data-dialog-target]");
const closeDialogButtons = document.querySelectorAll("dialog [data-close-dialog]");
const dialogForms = document.querySelectorAll("dialog form");
```

`querySelectorAll()` уже знаком по первым урокам. Селектор `dialog [data-close-dialog]` означает «элементы с атрибутом `data-close-dialog`, находящиеся внутри `dialog`». Аналогично `dialog form` находит формы внутри диалогов.

## 4. Открытие через `showModal()`

```javascript
dialogButtons.forEach((button) => {
  button.addEventListener("click", () => {
    const dialog = document.getElementById(button.dataset.dialogTarget);

    if (dialog instanceof HTMLDialogElement && !dialog.open) {
      dialog.showModal();
    } else if (dialog === null || !(dialog instanceof HTMLDialogElement)) {
      console.warn("Неизвестное диалоговое окно:", button.dataset.dialogTarget);
    }
  });
});
```

Разберём новые выражения.

**`button.dataset.dialogTarget`** читает из HTML значение атрибута `data-dialog-target`. Например, для кнопки «Создать проект» получается строка `"projectDialog"`. По ней метод `document.getElementById()` находит окно.

**`instanceof HTMLDialogElement`** проверяет, что найденный объект — именно элемент `<dialog>`, а не произвольный HTML-элемент со случайно совпавшим идентификатором. Это защищает нас от некорректной разметки.

**`!dialog.open`** проверяет, что окно ещё не открыто. Символ `!` означает логическое отрицание. Повторно открывать уже открытое окно не требуется.

Если идентификатор не найден или указывает на другой тип элемента, `console.warn()` выводит предупреждение в консоль. Приложение не пытается вызвать `showModal()` у постороннего элемента.

Обработчик один для всех кнопок «Добавить задачу», «Редактировать», «Создать проект» и «Пригласить участника», потому что нужный идентификатор записан в HTML.

## 5. Закрытие через `close()`

```javascript
closeDialogButtons.forEach((button) => {
  button.addEventListener("click", () => {
    const dialog = button.closest("dialog");

    if (dialog !== null && dialog.open) {
      dialog.close();
    }
  });
});
```

Новый метод **`closest("dialog")`** ищет ближайший подходящий элемент, поднимаясь от кнопки к её родителям в HTML. Кнопка «Отмена» вложена в форму, а форма — в конкретный `dialog`. Поэтому мы получаем именно то окно, внутри которого нажали «Отмена».

Проверка `dialog !== null && dialog.open` означает: окно найдено **и** открыто. Оператор `&&` — логическое «и». Только тогда вызывается `close()`.

Так один обработчик подходит всем трём окнам. Закрытие диалога **не переключает основной экран**: под окном остаётся тот раздел, из которого его открывали.

## 6. Почему мы перехватываем отправку форм

В каждом окне есть кнопка отправки формы, например «Сохранить задачу» с `type="submit"`. По умолчанию браузер может отправить форму и перезагрузить страницу. Но обработка данных ещё не реализована.

Чтобы учебное приложение не теряло текущий экран из-за такой попытки, на этом шаге вводим временное действие:

```javascript
dialogForms.forEach((form) => {
  form.addEventListener("submit", (event) => {
    event.preventDefault();
    console.info("Сохранение данных будет добавлено на следующих этапах.");
  });
});
```

Событие **`submit`** возникает при попытке отправить форму, в том числе после нажатия кнопки сохранения. Параметр **`event`** — объект со сведениями о событии. Метод **`event.preventDefault()`** отменяет стандартное действие браузера, то есть фактическую отправку формы. `console.info()` пишет пояснение в консоль разработчика.

Форма при этом остаётся открытой, данные никуда не отправляются и не сохраняются. Браузерная проверка обязательных полей продолжает работать, поскольку она выполняется перед событием `submit`.

**Важно:** мы не показываем ложное сообщение «Задача сохранена». Настоящее сохранение появится после введения модели задач и проектов.

## 8. Как проверить результат

1. Откройте Organizer, раздел **«Задачи»**. Нажмите **«Добавить задачу»**. Поверх страницы должно появиться окно с формой задачи.
2. Нажмите **«Отмена»** — окно закроется, а под ним останется экран задач.
3. Откройте окно ещё раз и нажмите **Escape** — оно должно закрыться стандартными средствами браузера.
4. Нажмите **«Редактировать»** на любой демонстрационной карточке задачи — откроется та же форма задачи. Пока она не заполнится данными карточки: это ожидаемое ограничение.
5. Перейдите в **«Проекты»**, нажмите **«Создать проект»** и закройте окно через «Отмена».
6. Перейдите в **«Команда»**, нажмите **«Пригласить участника»** и закройте окно.
7. Для проверки отправки формы заполните её обязательные поля и нажмите кнопку сохранения. **Ничего не сохранится**, страница не должна перезагрузиться, окно останется открытым. В консоли появится информационное сообщение.
8. После закрытия каждого окна проверьте, что выделение активного раздела сохранилось.

Для дополнительной проверки можно изменить в инструментах разработчика значение `data-dialog-target` кнопки на несуществующий идентификатор. При нажатии в консоли должно появиться предупреждение, а посторонний элемент не откроется.
