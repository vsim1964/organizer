# HTML-формы. Полный справочник элементов, полей и атрибутов

**Учебный справочник проекта Organizer** · HTML (без CSS и JavaScript)

Форма — часть HTML-страницы, с помощью которой пользователь вводит, выбирает и отправляет данные. HTML определяет элементы управления и правила их стандартной работы в браузере. Он сам по себе не сохраняет задачи в базе данных: для этого впоследствии понадобится обработка данных на сервере или посредством JavaScript.

## 1. Как устроена форма

Различайте четыре понятия.

- **Форма** — элемент `<form>`, объединяющий поля для отправки данных.
- **Элемент** — HTML-тег с определённой ролью: `<input>`, `<textarea>`, `<select>`, `<button>` и другие.
- **Тип поля** — значение атрибута `type` у `<input>`, например `text`, `date` или `checkbox`. Чекбокс — не отдельный HTML-тег.
- **Атрибут** — настройка элемента, записанная в открывающем теге: `id`, `name`, `required`, `value`, `min` и т. д.

```html
<form>
  <label for="taskTitle">Название задачи</label>
  <input type="text" id="taskTitle" name="title" required>
  <button type="submit">Сохранить</button>
</form>
```

В записи `<input type="text" id="taskTitle" name="title" required>`: элемент — `input`; тип — `text`; атрибуты — `type`, `id`, `name`, `required`.

**Важно:** «форма регистрации», «форма поиска» и «форма создания задачи» — названия по назначению, а не разные теги HTML. Их собирают из тех же строительных элементов.

## 2. Все основные элементы, относящиеся к формам

| Элемент | Назначение | Пример в Organizer |
|---|---|---|
| `<form>` | Объединяет элементы управления для отправки | Создание задачи |
| `<label>` | Подпись поля | «Название задачи» |
| `<input>` | Ввод и выбор; вид зависит от `type` | Название, дата, флажок |
| `<textarea>` | Многострочный текст | Описание |
| `<select>` | Список выбора | Приоритет |
| `<option>` | Вариант в `select` или `datalist` | «Высокий» |
| `<optgroup>` | Именованная группа вариантов в `select` | Группы исполнителей |
| `<button>` | Кнопка отправки, сброса либо другого действия | «Сохранить» |
| `<fieldset>` | Объединяет логически связанные поля | «Параметры доступа» |
| `<legend>` | Заголовок группы `fieldset` | «Кто видит задачу?» |
| `<datalist>` | Подсказки вариантов для совместимого `input` | Возможные названия проектов |
| `<output>` | Вывод результата расчёта или действия | Рассчитанная сумма |
| `<progress>` | Ход выполнения процесса | Загрузка вложения |
| `<meter>` | Значение на известной шкале | Занято 70% лимита |

`<progress>` и `<meter>` показывают состояние, а не вводят значения. `<output>` может участвовать в механизмах форм, но обычно не отправляет значение как обычное поле. `<datalist>` предоставляет подсказки, не являясь самостоятельным полем ввода.

Обычные элементы разметки — `<div>`, `<section>`, `<p>`, заголовки — тоже могут находиться внутри формы, но специальными элементами управления не считаются.

## 3. Все 22 стандартных типа input

Один тег `<input>` имеет 22 широко стандартизованных значения `type`. Если `type` не указан либо неизвестен браузеру, обычно используется поведение `text`.

### 3.1. Текст и адреса

| Тип | Для чего | Пример |
|---|---|---|
| `text` | Однострочный текст | Название задачи |
| `search` | Поисковый запрос | Поиск задач |
| `password` | Скрывает введённые символы на экране | Пароль |
| `email` | Адрес электронной почты, базовая проверка формата | Пригласить участника |
| `tel` | Телефон; встроенной проверки его формата нет | Контакт |
| `url` | Веб-адрес с базовой проверкой формата | Ссылка на источник |

```html
<input type="text" name="title">
<input type="email" name="email">
<input type="search" name="query">
```

`password` скрывает символы **визуально**, но само по себе не шифрует их. `email` и `url` проверяют синтаксис лишь в определённых пределах, а не существование адреса или сайта.

### 3.2. Числа, шкалы и цвет

| Тип | Для чего | Пример |
|---|---|---|
| `number` | Числовое значение | Количество часов |
| `range` | Ползунок для приблизительного выбора числа | Уровень готовности |
| `color` | Выбор цвета | Цвет проекта |

```html
<input type="number" name="hours" min="0" max="100" step="0.5">
<input type="range" name="progress" min="0" max="100" value="50">
<input type="color" name="projectColor" value="#3366cc">
```

`min` и `max` задают границы, `step` — допустимый шаг значений. Для данных вроде почтового индекса или номера телефона `number` обычно не подходит: это идентификаторы, а не количества.

### 3.3. Календарь и время

| Тип | Для чего | Пример значения |
|---|---|---|
| `date` | Дата | `2026-11-17` |
| `time` | Время | `14:30` |
| `datetime-local` | Местные дата и время, без часового пояса | `2026-11-17T14:30` |
| `month` | Год и месяц | `2026-11` |
| `week` | Год и номер недели (ISO) | `2026-W47` |

```html
<label for="dueDate">Срок выполнения</label>
<input type="date" id="dueDate" name="dueDate">
```

Внешнее представление даты зависит от браузера и языковых настроек; передаваемое значение `date` имеет вид `ГГГГ-ММ-ДД`. Поле `datetime-local` не содержит часового пояса. Поддержка специальных календарных интерфейсов различается между браузерами.

### 3.4. Выбор вариантов

| Тип | Для чего | Пример |
|---|---|---|
| `checkbox` | Независимый флажок: включён или выключен | Важная задача |
| `radio` | Выбор одного варианта в группе | Личная / командная задача |

```html
<label>
  <input type="checkbox" name="important" value="yes">
  Важная задача
</label>

<fieldset>
  <legend>Доступ</legend>
  <label><input type="radio" name="access" value="private" checked> Личный</label>
  <label><input type="radio" name="access" value="team"> Командный</label>
</fieldset>
```

У радиокнопок одной группы **одинаковый `name`**, а значения `value` различаются. Флажки могут отмечаться независимо. Неотмеченные `checkbox` и `radio` обычно не отправляют пару «имя — значение». У отмеченного флажка без заданного `value` значение при стандартной отправке — `on`.

### 3.5. Файл и скрытые данные

| Тип | Для чего | Пример |
|---|---|---|
| `file` | Выбор файла или файлов | Прикрепить документ |
| `hidden` | Невидимое для обычного отображения поле | Идентификатор записи |

```html
<input type="file" name="attachment" accept=".pdf,.txt">
<input type="hidden" name="taskId" value="123">
```

`hidden` **не защищает данные**: пользователь может увидеть и изменить их через инструменты разработчика. Проверять такие значения должен сервер. Для файлов пригодится атрибут `accept`, но он не гарантирует тип и безопасность загруженного файла.

### 3.6. Кнопки

| Тип | Для чего |
|---|---|
| `submit` | Отправить форму |
| `reset` | Восстановить первоначальные значения полей |
| `button` | Кнопка без стандартного действия; может использоваться с JavaScript |
| `image` | Графическая кнопка отправки формы |

```html
<input type="submit" value="Сохранить">
<input type="reset" value="Сбросить">
<input type="button" value="Дополнительно">
<input type="image" src="send.png" alt="Отправить">
```

`<button>` часто удобнее: внутри него допустим текст и другие элементы разметки. Его `type` следует задавать явно.

## 4. Атрибуты: общий справочник

Атрибуты имеют смысл **не у всех элементов сразу**. Ниже указаны основные области применения; они важнее, чем попытка запомнить атрибуты как общий список без привязки к тегу.

### 4.1. Идентификация и связь

| Атрибут | Для каких элементов | Что означает |
|---|---|---|
| `id` | Большинство элементов HTML | Уникальный идентификатор на странице |
| `name` | Управляющие элементы формы | Имя, под которым отправляется значение |
| `value` | `input`, `option`, `button` и др. | Значение элемента; конкретный смысл зависит от тега |
| `type` | `input`, `button` | Разновидность поля или кнопки |
| `for` | `label`, `output` | Связь с элементом по идентификатору; у `output` возможен список идентификаторов |
| `form` | Некоторые элементы управления | Ссылка на форму по её `id`, даже вне контейнера `form` |
| `list` | Поддерживаемые `input` | Идентификатор `datalist` с подсказками |

**Пример с подписью:**

```html
<label for="taskTitle">Название задачи</label>
<input id="taskTitle" name="title" type="text">
```

`for="taskTitle"` связывает подпись с полем `id="taskTitle"`. Атрибут `name="title"` определяет имя передаваемых данных. `id` и `name` могут совпадать, но выполняют разные задачи.

### 4.2. Ввод и внешний вид

| Атрибут | Основные элементы | Что означает |
|---|---|---|
| `placeholder` | Некоторые `input`, `textarea` | Подсказка в пустом поле; не заменяет `label` |
| `autocomplete` | `form` и поддерживаемые поля | Подсказка браузеру об автозаполнении |
| `inputmode` | Текстовые поля | Предпочтительная виртуальная клавиатура |
| `enterkeyhint` | Поля ввода | Подпись клавиши Enter на виртуальной клавиатуре |
| `autofocus` | Поддерживаемые элементы | Получить фокус при загрузке; использовать осторожно |
| `readonly` | Поддерживаемые `input`, `textarea` | Запрещает изменение, но поле обычно передаётся |
| `disabled` | Управляющие элементы | Отключает элемент; он не участвует в обычной отправке |
| `spellcheck` | Редактируемые элементы | Подсказка о проверке правописания |

`readonly` и `disabled` — разные состояния. Кроме того, `readonly` не применим ко всем разновидностям `input` (например, к флажкам).

### 4.3. Проверка и ограничения

| Атрибут | Основные элементы | Что означает |
|---|---|---|
| `required` | Поддерживаемые поля | Значение обязательно |
| `minlength` | Некоторые текстовые `input`, `textarea` | Минимальное число символов |
| `maxlength` | Некоторые текстовые `input`, `textarea` | Максимальное число символов |
| `min` | Числовые поля, даты и время | Нижняя граница |
| `max` | Числовые поля, даты и время | Верхняя граница |
| `step` | Числовые поля, даты и время | Шаг допустимых значений |
| `pattern` | Поддерживаемые текстовые `input` | Регулярное выражение для проверки ввода |
| `multiple` | `select`, `file`, `email` | Несколько выбранных значений, файлов или адресов |
| `novalidate` | `form` | Не запускать встроенную проверку при отправке формы |
| `formnovalidate` | Кнопки отправки | Пропустить встроенную проверку при отправке этой кнопкой |

**Логические атрибуты** (например, `required`, `checked`, `disabled`, `multiple`) включены уже своим присутствием. Запись `required="false"` не выключает `required` — атрибут по-прежнему присутствует.

```html
<label for="estimate">Часы работы</label>
<input type="number" id="estimate" name="estimate"
       min="0" max="24" step="0.5" required>
```

Браузерная проверка полезна, но **не заменяет проверку данных на сервере**: ограничения можно обойти.

### 4.4. Атрибуты отдельных элементов

| Атрибут | Элемент | Значение |
|---|---|---|
| `rows` | `textarea` | Приблизительная видимая высота в строках |
| `cols` | `textarea` | Приблизительная видимая ширина в символах |
| `wrap` | `textarea` | Как обрабатывать переносы строк при отправке |
| `size` | `input`, `select` | Ширина текстового поля или число видимых пунктов списка |
| `selected` | `option` | Изначально выбранный вариант |
| `checked` | `input type="checkbox"`, `input type="radio"` | Изначально отмеченный вариант |
| `label` | `option`, `optgroup` | Краткая подпись варианта или группы |
| `accept` | `input type="file"` | Предпочтительные типы файлов |
| `capture` | `input type="file"` | Подсказка об источнике съёмки на поддерживаемых устройствах |
| `src`, `alt` | `input type="image"` | Адрес изображения и альтернативный текст |
| `low`, `high`, `optimum` | `meter` | Пороговые и оптимальное значения шкалы |
| `max`, `value` | `progress` | Максимум и степень выполнения |
| `dirname` | Поддерживаемые текстовые элементы | Имя отдельного параметра для направления текста |

```html
<label for="description">Описание</label>
<textarea id="description" name="description" rows="4"></textarea>
```

Для `textarea` начальное содержимое записывается **между открывающим и закрывающим тегами**, а не через атрибут `value`.

## 5. Списки select, option и optgroup

```html
<label for="taskPriority">Приоритет задачи</label>
<select id="taskPriority" name="priority" required>
  <option value="">Выберите приоритет</option>
  <option value="low">Низкий</option>
  <option value="medium">Средний</option>
  <option value="high">Высокий</option>
</select>
```

Текст между тегами `option` показывают пользователю; атрибут `value` задаёт передаваемое значение. При выборе «Высокий» отправляется `priority=high`.

`required` для обычного одиночного списка позволяет потребовать выбор содержательного значения, если первый вариант имеет пустой `value`.

**Группы вариантов:**

```html
<select name="assignee">
  <optgroup label="Разработчики">
    <option value="alex">Алексей</option>
    <option value="maria">Мария</option>
  </optgroup>
  <optgroup label="Редакторы">
    <option value="ivan">Иван</option>
  </optgroup>
</select>
```

При `multiple` можно выбрать несколько вариантов. В обычной отправке одно имя тогда может встречаться несколько раз.

## 6. Подсказки datalist: не то же самое, что select

```html
<label for="project">Проект</label>
<input id="project" name="project" list="projectSuggestions">
<datalist id="projectSuggestions">
  <option value="Organizer"></option>
  <option value="Учебный курс"></option>
  <option value="Личный проект"></option>
</datalist>
```

`select` обычно ограничивает выбор заранее определёнными вариантами. `datalist` лишь предлагает подходящие значения: в текстовое поле можно ввести и другой текст. Поведение подсказок и поддерживаемые виды `input` зависят от браузера.

## 7. Как связаны label, fieldset и legend

`label` объясняет отдельное поле. Связь задаётся через совпадение `for` и `id` либо через вложение поля в `label`. При нажатии на правильно связанную подпись обычно активируется соответствующее поле.

`fieldset` объединяет родственные элементы, а `legend` даёт группе имя. Для группы переключателей это особенно полезно.

```html
<fieldset>
  <legend>Видимость задачи</legend>
  <label><input type="radio" name="visibility" value="private" checked> Только мне</label>
  <label><input type="radio" name="visibility" value="team"> Команде</label>
</fieldset>
```

Не заменяйте видимую подпись одним `placeholder`: подсказка может исчезнуть во время ввода.

## 8. Отправка формы: form и button

### 8.1. Основные атрибуты form

| Атрибут | Что делает |
|---|---|
| `action` | URL обработчика, которому браузер отправляет форму |
| `method` | Метод отправки: обычно `get` или `post`; есть также специальное значение `dialog` |
| `enctype` | Формат кодирования данных при `post` |
| `target` | Куда открыть ответ, например `_self` или `_blank` |
| `accept-charset` | Кодировка отправки; в современных HTML-формах используется UTF-8 |
| `autocomplete` | Режим автозаполнения по умолчанию |
| `name` | Имя самой формы |
| `novalidate` | Отключить встроенную проверку перед отправкой |
| `rel` | Отношение к адресу назначения (в поддерживаемых случаях) |

`method="get"` обычно добавляет пары «имя — значение» к URL; удобно для поиска, но не для секретных данных. `method="post"` передаёт данные в теле запроса. `POST` **не шифрует** передачу: для защиты нужен HTTPS.

Обычно используется `enctype="application/x-www-form-urlencoded"`. Для отправки файлов необходим `enctype="multipart/form-data"`. Есть и `text/plain`, но его редко используют для обычных приложений.

Значение `method="dialog"` применяется к форме внутри диалогового элемента `<dialog>`: оно закрывает диалог вместо обычной сетевой отправки.

### 8.2. Три вида button

```html
<button type="submit">Сохранить</button>
<button type="reset">Сбросить</button>
<button type="button">Отмена</button>
```

| `type` | Что делает |
|---|---|
| `submit` | Запускает отправку формы |
| `reset` | Возвращает поля к исходным значениям |
| `button` | Не запускает встроенного действия |

**Внутри формы** `<button>` без явного `type` обычно действует как `submit`. Лучше писать тип всегда. Кнопка `type="button"` для действия «Отмена» будет работать только после добавления соответствующей логики.

Кнопка отправки может переопределять настройки формы атрибутами `formaction`, `formmethod`, `formenctype`, `formtarget` и `formnovalidate`.

### 8.3. Что браузер отправляет

```html
<form action="/tasks" method="post">
  <input name="title" value="Прочитать главу">
  <select name="priority">
    <option value="high" selected>Высокий</option>
  </select>
  <button type="submit">Сохранить</button>
</form>
```

Отправляемые данные содержат пары `title=Прочитать главу` и `priority=high`. Поля без `name`, отключённые поля и неотмеченные флажки в обычную отправку не попадают. Из нескольких кнопок отправки включается значение только той кнопки, которая инициировала отправку, если у неё есть `name`.

Путь `/tasks` здесь **условный пример**. В текущем учебном Organizer обработчик отправки по этому адресу может отсутствовать.

## 9. Встроенная проверка браузера

Для поддерживаемых полей браузер может проверять обязательность заполнения (`required`), тип (`email`, `url`), допустимую длину, диапазон чисел и дат, шаг (`step`), шаблон (`pattern`). Обычно недопустимые значения мешают стандартной отправке.

```html
<label for="userEmail">Электронная почта</label>
<input id="userEmail" type="email" name="email" required>

<label for="title">Название</label>
<input id="title" type="text" name="title"
       minlength="3" maxlength="100" required>
```

`minlength` и `maxlength` измеряют длину текста, тогда как `min` и `max` задают границы значения. `pattern` использует регулярное выражение; к его изучению вернёмся при освоении JavaScript.

Не все атрибуты работают со всеми типами. Например, `required` не делает обязательным `input type="hidden"`. Проверки браузера недостаточно для безопасности или достоверности данных.

## 10. Отображение результатов: output, progress и meter

```html
<output name="totalHours">8</output>

<label for="uploadProgress">Загрузка файла</label>
<progress id="uploadProgress" value="40" max="100">40%</progress>

<label for="storageUsage">Использование места</label>
<meter id="storageUsage" min="0" max="100"
       low="30" high="80" optimum="20" value="70">70%</meter>
```

`output` представляет результат вычисления или действия. `progress` — ход выполнения процесса. `meter` — измеряемую величину на заранее известной шкале. Для прогресса задачи `progress` часто подходит лучше, чем `meter`; для использования дискового пространства — наоборот.

## 11. Доступность и удобство

Используйте понятные `label`, а группы `radio` и связанных флажков объединяйте `fieldset` с `legend`. Не полагайтесь только на цвет или на `placeholder`. У поля должна быть ясная подпись, даже если визуально оно выглядит очевидным.

Сохраняйте логичный порядок полей в HTML: по нему пользователь перемещается с клавиатуры. `disabled` не подходит для данных, которые пользователь должен просмотреть и отправить без редактирования: там иногда лучше `readonly` (если тип поля его поддерживает).

Атрибуты `aria-label`, `aria-labelledby` и `aria-describedby` помогают уточнять назначение и пояснения элементов, но не должны без нужды заменять обычные подписи HTML.

## 12. Частые ошибки

1. Перепутать `id` и `name`. Первый идентифицирует элемент, второй называет отправляемое значение.
2. Написать `<label for="title">`, когда `id` поля — `taskTitle`: связь не установится.
3. Оставить пустой `label` или полагаться только на `placeholder`.
4. Считать `checkbox` и `radio` самостоятельными HTML-тегами: это типы `input`.
5. Не дать группе `radio` общего `name`: переключатели перестанут быть единой группой.
6. Ждать от неотмеченного `checkbox` значения `false`: обычно он вообще не отправляется.
7. Писать `required="false"`, ожидая отключения проверки.
8. Считать `hidden` защищённым от просмотра и изменения.
9. Не указывать `type="button"` для обычной кнопки внутри формы: она может отправить форму.
10. Путать `reset` с очисткой: он восстанавливает **исходные** значения, не обязательно пустые.
11. Использовать `input type="number"` для телефонных номеров и кодов с ведущими нулями.
12. Рассчитывать, что HTML сам сохранит данные задачи в базе.
13. Доверять исключительно проверке в браузере, не проверяя значения на сервере.

## 13. Образец формы Organizer для чтения и разбора

Это **справочный пример**, а не задание переписать действующий `form.html` целиком.

```html
<form action="/tasks" method="post">
  <label for="taskTitle">Название задачи</label>
  <input type="text" id="taskTitle" name="title" required
         maxlength="100">

  <label for="taskDescription">Описание задачи</label>
  <textarea id="taskDescription" name="description" rows="4"></textarea>

  <label for="taskPriority">Приоритет</label>
  <select id="taskPriority" name="priority" required>
    <option value="">Выберите приоритет</option>
    <option value="low">Низкий</option>
    <option value="medium">Средний</option>
    <option value="high">Высокий</option>
  </select>

  <label for="taskDueDate">Срок выполнения</label>
  <input type="date" id="taskDueDate" name="dueDate">

  <label>
    <input type="checkbox" name="important" value="yes">
    Важная задача
  </label>

  <fieldset>
    <legend>Видимость</legend>
    <label>
      <input type="radio" name="visibility" value="private" checked>
      Личная
    </label>
    <label>
      <input type="radio" name="visibility" value="team">
      Для команды
    </label>
  </fieldset>

  <button type="submit">Сохранить</button>
  <button type="reset">Сбросить</button>
</form>
```

Здесь `action="/tasks"` — **условный адрес**. Сама разметка задаёт поля и отправку, но не реализует сохранение задач.

## 14. Что запомнить в первую очередь

**`form`** объединяет поля; **`input`** создаёт поле определённого **`type`**; **`textarea`** позволяет вводить многострочный текст; **`select`** и **`option`** задают варианты; **`label`** подписывает поле; **`fieldset`** и **`legend`** группируют связанные поля. Атрибуты **`id`** и **`for`** обеспечивают связь подписи с полем, **`name`** и значение поля отвечают за передаваемые данные, **`required`** и другие ограничения помогают браузеру проверять ввод.

**Порядок изучения в Organizer:** текстовые поля → `textarea` → `select` → даты → флажки и переключатели → проверка и отправка. Этот справочник шире текущих уроков: незнакомые разделы предназначены для последующего обращения. CSS и JavaScript будем изучать позже.
