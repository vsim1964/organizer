# HTML-формы: элементы, типы полей и атрибуты

Учебная памятка для проекта **Organizer**. В ней собраны основные средства HTML для создания форм. HTML задаёт состав полей, допустимые способы ввода и некоторые правила проверки. Сохранение задачи в базе данных потребует дальнейшей программной логики.

## 1. Три понятия: элемент, тип и атрибут

**Элемент HTML** — часть разметки с определённым назначением. Например, `<input>` создаёт поле ввода, `<textarea>` — многострочное текстовое поле, `<select>` — список вариантов.

**Тип поля** — разновидность элемента `<input>`, указанная атрибутом `type`. Например, `<input type="text">` предназначен для обычного текста, а `<input type="date">` — для даты.

**Атрибут** — дополнительное указание внутри открывающего тега. В записи `<input type="text" name="title" required>` атрибут `type` задаёт тип поля, `name` — имя данных при отправке, а `required` — обязательность заполнения.

Слово *форма* в строгом смысле относится к элементу `<form>`, который объединяет элементы управления. «Формой» часто называют и весь видимый набор полей.

## 2. Основные элементы формы

| Элемент | Назначение | Пример для Organizer |
|---|---|---|
| `<form>` | Объединяет поля для отправки данных | Создание задачи |
| `<label>` | Даёт полю понятную подпись | «Название задачи» |
| `<input>` | Поле ввода; поведение зависит от `type` | Название, дата, поиск |
| `<textarea>` | Ввод текста в несколько строк | Описание задачи |
| `<select>` | Выбор из списка | Приоритет задачи |
| `<option>` | Один вариант в списке | «Высокий» |
| `<button>` | Кнопка, в том числе отправки или сброса | «Сохранить» |
| `<fieldset>` | Группирует связанные элементы формы | Параметры задачи |
| `<legend>` | Заголовок группы `<fieldset>` | «Сроки» |
| `<optgroup>` | Группирует варианты внутри `<select>` | Группы проектов |

### Простая форма

```html
<form action="/tasks" method="post">
  <label for="taskTitle">Название задачи</label>
  <input id="taskTitle" name="title" type="text" required>
  <button type="submit">Сохранить</button>
</form>
```

Здесь `action="/tasks"` — **учебный пример адреса**: в текущем Organizer обработчик по такому адресу ещё не создан. Если кнопку нажать сейчас, сохранение задачи само собой не произойдёт.

## 3. Типы элемента input

Все приведённые ниже записи используют один и тот же элемент `<input>`, но различаются значением атрибута `type`.

| `type` | Для чего нужен | Пример |
|---|---|---|
| `text` | Короткий текст | Название задачи |
| `search` | Поисковый запрос | Поиск задач |
| `email` | Адрес электронной почты с базовой проверкой формата | Приглашение участника |
| `password` | Ввод с визуальным скрытием символов | Пароль |
| `number` | Числовое значение | Оценка трудозатрат |
| `tel` | Номер телефона; сам по себе не проверяет его формат | Контакт |
| `url` | Веб-адрес с базовой проверкой формата | Ссылка на материал |
| `date` | Календарная дата | Срок выполнения |
| `time` | Время | Время напоминания |
| `datetime-local` | Местная дата и время, без часового пояса | Назначение встречи |
| `month` | Месяц и год | Отчётный месяц |
| `week` | Неделя и год | Планирование по неделям |
| `checkbox` | Независимый флажок: отмечено или нет | «Важная задача» |
| `radio` | Один вариант из группы с одинаковым `name` | Тип доступа |
| `file` | Выбор файла для загрузки | Вложение |
| `hidden` | Значение без видимого поля; **не скрывает данные от пользователя технически** | Идентификатор задачи |
| `range` | Выбор значения на шкале | Примерная готовность |
| `color` | Выбор цвета | Цвет проекта |
| `submit` | Отправка формы | Альтернатива кнопке `button` |
| `reset` | Возврат полей к первоначальным значениям | Сброс формы |
| `button` | Кнопка без встроенного действия | Будущая команда JavaScript |

Редко используемые разновидности `<input>` можно изучать по мере необходимости. Не все типы одинаково выглядят в разных браузерах.

## 4. Атрибуты: что они означают

### Идентификация и передача данных

| Атрибут | У каких элементов применяется | Значение |
|---|---|---|
| `id` | У большинства HTML-элементов | Уникальный идентификатор элемента на странице |
| `name` | У элементов управления формой | Имя, под которым значение передаётся при отправке |
| `value` | У многих элементов управления, включая `<option>` | Значение поля или варианта |
| `for` | `<label>` | Указывает `id` поля, к которому относится подпись |
| `type` | `<input>`, `<button>` | Задаёт разновидность поля или действие кнопки |
| `form` | У некоторых элементов управления | Связывает элемент с формой по её `id`, даже если он находится вне `<form>` |

**Не путайте `id` и `name`.** `id` нужен для обращения к конкретному элементу страницы и связывания с подписью. `name` называет передаваемое значение. В обычной HTML-форме данные отправляются как пары «имя — значение».

```html
<label for="taskPriority">Приоритет</label>
<select id="taskPriority" name="priority">
  <option value="low">Низкий</option>
  <option value="high">Высокий</option>
</select>
```

Если выбран пункт «Высокий», в данных формы будет пара `priority=high`. `priority` взято из `name` списка, `high` — из `value` выбранного варианта. Человек видит надпись «Высокий».

### Подсказки, обязательность и ограничения

| Атрибут | Назначение |
|---|---|
| `placeholder` | Показывает пример или подсказку в пустом поле; **не заменяет `label`** |
| `required` | Требует заполнить поле перед обычной отправкой формы |
| `minlength` | Минимальное количество символов для некоторых текстовых полей |
| `maxlength` | Максимальное количество вводимых символов |
| `min` | Минимально допустимое значение числа или даты (если применимо) |
| `max` | Максимально допустимое значение числа или даты (если применимо) |
| `step` | Шаг изменения числа либо времени (если применимо) |
| `pattern` | Шаблон проверки для поддерживаемых текстовых полей |
| `readonly` | Запрещает редактирование, но обычно сохраняет поле в отправляемых данных |
| `disabled` | Отключает управление; его значение обычно **не отправляется** |
| `autocomplete` | Подсказывает браузеру, какие данные он может автоматически подставить |

Атрибуты наподобие `required`, `disabled` и `readonly` называют **логическими**: для включения свойства достаточно их присутствия в теге, например `<input required>`.

Ограничения HTML помогают пользователю и браузеру, но **не заменяют проверку на сервере**.

### Многострочный текст и варианты выбора

| Атрибут | Где используется | Значение |
|---|---|---|
| `rows` | `<textarea>` | Примерное число видимых строк |
| `cols` | `<textarea>` | Примерная ширина в символах |
| `multiple` | `<select>`, некоторые `<input>` | Разрешает выбор нескольких значений или файлов |
| `selected` | `<option>` | Вариант, выбранный первоначально |
| `checked` | `checkbox`, `radio` | Отмечено первоначально |
| `size` | `<select>` и некоторые `<input>` | Размер представления; смысл зависит от элемента |

Текст по умолчанию внутри `<textarea>` помещают **между тегами**, а не в атрибут `value`:

```html
<label for="taskDescription">Описание задачи</label>
<textarea id="taskDescription" name="description" rows="4"></textarea>
```

### Атрибуты самой формы

| Атрибут | Назначение |
|---|---|
| `action` | Адрес, куда браузер отправляет данные формы |
| `method` | HTTP-метод отправки; чаще `get` или `post` |
| `enctype` | Способ кодирования отправляемых данных; для обычной загрузки файлов нужен `multipart/form-data` |
| `novalidate` | Отключает встроенную проверку формы перед отправкой |

При `method="get"` данные обычно попадают в адресную строку как параметры URL. При `method="post"` данные передаются в теле HTTP-запроса. Сам по себе `post` **не шифрует** данные: защита передачи зависит, в частности, от HTTPS.

## 5. Как читать запись HTML

```html
<input type="date" id="dueDate" name="dueDate" required>
```

- `input` — элемент ввода.
- `type="date"` — выбор календарной даты.
- `id="dueDate"` — уникальный идентификатор для подписи и других обращений к полю.
- `name="dueDate"` — имя будущего передаваемого значения.
- `required` — поле обязательно для заполнения при стандартной отправке.

У `<input>` нет закрывающего тега. У `<textarea>` и `<select>` они есть.

## 6. Кнопки: три распространённых варианта

```html
<button type="submit">Сохранить</button>
<button type="reset">Очистить</button>
<button type="button">Дополнительное действие</button>
```

`submit` запускает стандартную отправку формы; `reset` восстанавливает исходные значения полей; `button` сам по себе ничего не делает — позднее его можно связать с JavaScript. **Внутри формы у `<button>` без `type` по умолчанию обычно поведение `submit`**, поэтому тип лучше писать явно.

## 7. Группы выбора: checkbox и radio

Флажки позволяют независимо включать несколько вариантов:

```html
<label><input type="checkbox" name="important" value="yes"> Важная</label>
```

Если флажок не отмечен, браузер обычно не передаёт для него пару `important=...`.

Переключатели `radio` с одинаковым `name` образуют одну группу, в которой можно выбрать лишь один вариант:

```html
<fieldset>
  <legend>Доступ к задаче</legend>
  <label><input type="radio" name="access" value="private"> Личный</label>
  <label><input type="radio" name="access" value="team"> Командный</label>
</fieldset>
```

## 8. Поле даты: тема следующего урока

```html
<label for="taskDueDate">Срок выполнения</label>
<input type="date" id="taskDueDate" name="dueDate">
```

Браузер обычно предлагает интерфейс календаря. Отображение даты зависит от браузера и языковых настроек. **Значение даты** при отправке имеет формат `ГГГГ-ММ-ДД`, например `2026-11-17`.

## 9. Типичные ошибки

1. Написать `<label for="title">`, когда у поля `id="taskTitle"`: подпись не будет связана с нужным полем.
2. Оставить `<label></label>` пустым: поле останется без понятной подписи.
3. Заменить подпись `label` подсказкой `placeholder`: подсказка может исчезнуть при вводе.
4. Перепутать `name` и `value` у списка: `name` принадлежит самому `<select>`, а значения вариантов задаются через `<option value="...">`.
5. Поместить кнопку отправки между полями вместо логичного завершения формы.
6. Думать, что HTML-форма автоматически сохраняет введённые данные в базу: для сохранения необходим обработчик.
7. Рассчитывать только на `required` как на защиту данных: на сервере данные нужно проверять отдельно.

## 10. Краткая схема запоминания

**`form`** — что отправляем вместе. **`label`** — как называем поле для человека. **`input` / `textarea` / `select`** — как человек вводит или выбирает данные. **`option`** — из чего выбирает. **`id` + `for`** — как связываем подпись с полем. **`name` + значение поля** — какая пара данных отправляется. **`required` и другие ограничения** — какие требования браузер проверяет до отправки. **`button type="submit"`** — действие отправки.
