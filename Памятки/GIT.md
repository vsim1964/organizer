# Git и GitHub — памятка для проекта Organizer

В проекте **Organizer** мы работаем с двумя копиями репозитория: локальной (в VS Code на компьютере) и удалённой (на GitHub). Основная ветка — `main`.

## 1. Как отправить свою работу на GitHub

После выполнения задания откройте терминал в папке проекта и выполните:

```bash
git status
git add .
git commit -m "Краткое описание изменений"
git push
```

- `git status` — показывает состояние файлов и ветки.
- `git add .` — добавляет изменения в область подготовки к коммиту. Перед этим убедитесь, что среди них нет лишних или секретных файлов.
- `git commit -m "…"` — создаёт коммит **в локальном репозитории**.
- `git push` — отправляет локальные коммиты в удалённый репозиторий GitHub.

После `git push` сообщите в чате, что работа готова к проверке.

## 2. Как принять изменения, предложенные через Pull Request

Когда ассистент предлагает изменения:

1. Он создаёт отдельную ветку, вносит изменения и открывает **Pull Request (PR)** в ветку `main`.
2. Вы открываете ссылку на PR и изучаете вкладку **Files changed**.
3. Если всё устраивает, нажимаете **Merge pull request**, затем **Confirm merge**.
4. В терминале VS Code, находясь в своей локальной ветке `main`, выполняете:

```bash
git pull
```

Полученные изменения уже включены в историю Git. **Дополнительный `git commit` после успешного `git pull` не требуется**, если вы не делали своих новых изменений.

## 3. Проверка синхронизации

```bash
git status
```

При отсутствии локальных изменений и после синхронизации обычно появится:

```text
On branch main
Your branch is up to date with 'origin/main'.

nothing to commit, working tree clean
```

Если Git сообщает об изменённых файлах, сначала разберитесь с ними. Не запускайте `git pull` вслепую при незакоммиченных изменениях — может потребоваться сначала сохранить работу коммитом или временно отложить её.

## 4. Краткая схема работы

**Ваша работа:** редактирование в VS Code → `git status` → `git add .` → `git commit` → `git push` → проверка ассистентом.

**Мои предложения:** отдельная ветка → коммит → Pull Request → ваша проверка → Merge → `git pull` на вашем компьютере.

### Запомните

- **`commit`** сохраняет версию локально.
- **`push`** отправляет коммиты на GitHub.
- **`pull`** получает изменения с GitHub и интегрирует их в текущую ветку.
- **Pull Request** — предложение объединить изменения одной ветки с другой, которое можно изучить до принятия.

Перед работой полезно выполнить `git status` и, если локальное состояние позволяет, `git pull`. После работы — проверить изменения, создать коммит и выполнить `git push`.
